# OhMyPassword 本地服务与单向接收

桌面端与 Android / iOS 共用的 Rust 服务。0.2.3 的局域网发现与接收使用**协议 3**；本机浏览器接口继续使用**协议 2**。密码库格式仍由 `ohmypassword-core` 管理。服务不提供网络解锁接口；锁定或暂停时不能读取密码、批准请求或继续接收。

## 浏览器接口

仅监听 `127.0.0.1:17841`，官方 Chrome / Edge 插件无需填写 token。服务通过 `browser-origin.txt` 固定插件 Origin，校验准确的 Host、Origin、JSON 类型与解锁状态；普通网页、其他扩展、缺少 Origin 的密码请求均被拒绝。旧 token 和客户端授权表不参与判断。

| 接口 | 请求 | 响应 |
| --- | --- | --- |
| `GET /v1/status` | 无凭据 | `{protocol:2, initialized, locked}`，不含库内容 |
| `POST /v1/browser/connect` | 官方插件 Origin | `{connected:true, protocol:2}` |
| `POST /v1/credentials/search` | JSON `{hostname}` | `{entries:[…]}`，按可注册主域名匹配，保留每条记录的完整 hostname |
| `POST /v1/credentials` | JSON `EntryInput` | `{entry:…}`，只保存本机 |

浏览器路径保留 `/v1`，响应明确标识协议 2，与 LAN 协议版本独立。Chromium 扩展的跨域 GET 可能省略 Origin，因此插件使用 POST 搜索；兼容 GET 搜索仍严格要求 Origin。接口不需要 `Authorization`，预检只允许 `Content-Type`；所有响应禁止缓存。公开状态接口可供插件区分“服务未运行”和“密码库已锁定”。

固定 Origin 用于隔离网页和非官方扩展；它不能认证拥有本机进程权限的程序。

## 设备发现

- 默认每 **300 秒**检测一次，用户也可调用 `detect_devices()`；手动检测或恢复应用后重新安排下一轮检测。每轮浏览 20 秒，设备列表保留最近 660 秒内实际发现的结果。
- 桌面使用 `_ohmypassword._tcp.local.` mDNS-SD，TXT 为 `protocol=3` 和 `device_id`；手机通过原生 NSD / Bonjour 将新结果交给服务。不发现旧版双向协议设备，广播不包含密码或密钥。
- 检测只更新设备列表。新增、修改、删除密码、浏览器保存、解锁和恢复应用，都不会触发密码传输。
- 首版支持 IPv4 私网、回环和链路本地地址。LAN 服务默认端口 `17842`；只使用数字 IP，不解析远端 URL 主机名、不跟随重定向、不使用系统代理。

## 一次性单向接收

1. 需要密码的发起方从已发现设备中选择「接收对方密码」，`request_merge(device_id)` 返回单次会话。后台只进行握手，不读取或发送密码。
2. 双方先交换对临时 X25519 公钥与随机 nonce 的承诺，再揭示并验证。会话密钥与六位核对编号由 HKDF 派生，绑定双方设备 ID、公钥、nonce、服务 epoch 和会话 ID；拒绝无效或全零共享密钥。
3. 两端核对屏幕上的相同编号后，发起方确认接收，提供方允许提供。编号无需输入或复制，不使用邀请码，也不建立长期配对授权。握手未完成、只有一端确认、拒绝或过期时不能开始密码传输。
4. 发起方发送加密的空 `pull` 请求，不附本机密码。提供方只读取 `export_pull()`：每条当前有效记录取最新版本，不包含删除标记或全部历史，返回快照及摘要。提供方不调用导入或保存，不写入密码库。
5. 发起方通过 `import_pull()` 按 ID/版本合并，拒绝删除标记；缺少记录或空来源不删除本机数据。有实际变更时先保存独立加密备份，再原子写入，保留本机已有历史。较新的本地删除仍有效，较旧导入版本只能补入历史，需用户显式恢复。
6. 发起方成功持久化后发送该快照摘要的 ACK。提供方只确认这份已提供快照的回执，不比较双方整库是否相等。最终 ACK 窗口对发起方使用短暂写保护，提供方仍可自己编辑。丢失 ACK 可通过同一请求缓存或加密状态回执确认。

密码快照经 AES-256-GCM 加密，AAD 绑定方向、路由、设备 ID、会话 ID、请求 ID 与 epoch；承诺、密文和 HKDF 上下文均使用协议 3。当前 LAN 路由：

| 路由 | 用途 |
| --- | --- |
| `GET /v3/info` | 协议与当前服务信息 |
| `POST /v3/merge/request`、`/v3/merge/reveal` | 建立单次确认会话 |
| `POST /v3/merge/{id}/status` | 加密状态与完成回执查询 |
| `POST /v3/merge/{id}/pull` | 已确认会话内只读导出有效记录 |
| `POST /v3/merge/{id}/ack` | 确认请求方已保存本次快照 |
| `POST /v3/merge/{id}/cancel` | 取消未完成会话 |

完成后，发起方界面显示「已合并密码本」，提供方显示「已向对方提供密码，本机密码未修改」。`received_count` 为请求方收到的有效记录数，`changed_count` 为新写入的修订数（可能仅补历史），`source_count` 为提供方发送记录数。空来源明确提示没有可接收的密码；UI 会核对刷新结果，不把这些计数等同于最终可见账号数。

拒绝、取消、超时、锁定或退出会停止本轮。网络中断时，请求方可能已保存却尚未取得完成回执；这些记录会保留，不伪装成已回滚。提供方不会因失败而需要数据回滚，因为接收流程从未写入其密码库。之后的编辑只留在各自本机，需要密码的另一方必须另行发起接收。

会话最长五分钟。锁定/暂停时清除会话密钥、请求记录和发现列表，并轮换服务 epoch，旧编号与迟到请求不能恢复授权。完成后的短期会话仅允许回执查询和原 ACK 幂等重试，不能再次读取新密码。旧 `/v2/merge/*`、`/v1/pair` 和 `/v1/sync` 路由均不提供，不自动降级，也不会因旧磁盘配对信息而启用旧流程。

## 资源与边界

核心密码记录及历史合计上限 1 MiB，HTTP 消息上限 2 MiB（包含加密/Base64 开销）。容量、备份或落盘失败不会部分覆盖本机密码库。加密整库备份最多保留 64 个目录项，到限后拒绝新的有变更导入/恢复，要求用户先归档，不自动清理旧副本。恢复步骤见 [RECOVERY.md](../../RECOVERY.md)。

处理中的 HTTP 请求上限为 8，LAN 每个源地址每分钟最多 64 个请求；网络请求设有超时，服务停止具有有限等待。这不是 TCP 层抗拒绝服务保证。手机仅在系统允许运行且密码库解锁时检测/接收，不承诺后台常驻。不同网段、Wi-Fi 客户端隔离和防火墙可能阻止设备直连。

## 验证

```sh
cargo test --locked --manifest-path desktop/service/Cargo.toml
```

测试使用真实本机 HTTP 套接字和独立加密密码库，检查免 token 官方插件接口、非法 Origin/Host、发现不传输、双端手动确认、拒绝/锁定/到期、版本合并、旧协议拒绝、容量失败、commit-reveal/全零密钥、单次授权、防重放、ACK 幂等、最终写保护与丢失 ACK 恢复。单向回归还核对空请求方取得密码、提供方内存与磁盘不变、请求方删除/独有记录不回传、空来源不清空本机和保存失败不成功。结果以根目录 [验证记录](../../VALIDATION.md) 为准；真实手机、跨设备 mDNS 和各类局域网仍需实测。
